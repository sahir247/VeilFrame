I inspected the current `main` branch of Sahir247/VeilFrame, commit `18e499d1d0fca86eb664cafca8483c96524071fa` (30 October 2026).

I’m treating this as a source-level JNI audit—not assuming that a function is safe merely because it compiles or has been exercised on a device. I checked the matting, PII detection, RIFE, and RealSR JNI bridges, focusing on bitmap memory, native resource lifetime, input validation, tensor handling, callbacks, and failure paths.

Important distinction: JNI is implemented across these subsystems, but I found several places where the implementation still deserves hardening. That does not mean the normal tested workflow is necessarily broken.

### Findings

1. PII detector: missing bitmap-format validation

File: `pii_ncnn_jni.cpp`, approximately lines 161–190 and 263–293.

Both `nativeDetectFaces()` and `nativeDetectPii()` retrieve bitmap information and then interpret the pixel memory as RGBA:

```cpp
ncnn::Mat in = ncnn::Mat::from_pixels_resize(
    reinterpret_cast<const unsigned char*>(pixels),
    ncnn::Mat::PIXEL_RGBA2RGB,
    orig_w, orig_h,
    static_cast<int>(info.stride),
    ...
);
```

Unlike the matting and RIFE bridges, these functions do not check:

```cpp
info.format == ANDROID_BITMAP_FORMAT_RGBA_8888
```

If an unexpected bitmap format reaches these methods, the conversion interprets its memory incorrectly.

Fix: Validate bitmap format, dimensions and pixel pointer before conversion in both functions. Reject unsupported formats rather than guessing.

2. RIFE: unchecked dimensions and timestep

File: `rife_jni.cpp`, approximately lines 134–220.

Two issues:

* `pixel_count = w * h` uses signed `int` multiplication before conversion to `size_t`. Extremely large dimensions can overflow.

* `timestep` is passed directly into inference without checking whether it is finite or within the valid interpolation interval.

Recommended validation:

```cpp
if (w <= 0 || h <= 0 ||
    static_cast<uint64_t>(w) * h > MAX_PIXELS ||
    !std::isfinite(timestep) ||
    timestep < 0.0f || timestep > 1.0f) {
    return nullptr;
}
```

Use a project-appropriate `MAX_PIXELS`, and perform multiplication in 64-bit arithmetic.

There is also an unchecked `GetStringUTFChars()` in `nativeInit()`. If it returns null, constructing `std::string` from the pointer is unsafe.

3. RIFE: GPU instance lifecycle is not coordinated across subsystems

File: `rife_jni.cpp`, approximately lines 277–300.

`nativeRelease()` calls:

```cpp
ncnn::destroy_gpu_instance();
```

RIFE maintains its own `g_rife_gpu_instance_created` flag, while RealSR has a separate global NCNN GPU initialization and teardown lifecycle.

This creates a potential shared-resource ownership problem: one subsystem can destroy the global Vulkan instance while another subsystem still has GPU-backed resources.

Whether this becomes an actual failure depends on the order in which the application initializes and releases these engines.

Fix: Use a process-wide Vulkan/NCNN GPU lifecycle manager with reference counting or centralized ownership. Individual model engines should not independently destroy a shared global GPU instance.

4. Matting: unchecked JNI string acquisition

File: `matting_jni.cpp`, approximately lines 27–90.

The code calls:

```cpp
const char* param_c = env->GetStringUTFChars(paramPath, nullptr);
const char* bin_c = env->GetStringUTFChars(binPath, nullptr);
```

Neither pointer is checked before use.

If acquisition fails, the code can pass a null pointer to NCNN or attempt to release an invalid string pointer.

Also, `modelType` is not validated. Any value other than `MODEL_U2NETP` selects MODNet.

Fix: Validate both Java strings and the model type before creating or replacing the model instance. Handle partial acquisition correctly.

5. Matting: missing inference tensor validation

File: `matting_jni.cpp`, approximately lines 190–280.

The extraction return code is checked, which is good. However, the output tensor is subsequently assumed to have a valid shape and usable channel zero.

For example:

```cpp
float* ptr = out_unpadded.channel(0);
const int size = out_unpadded.w * out_unpadded.h;
```

There is no explicit validation of:

* Output tensor dimensions.

* Channel count.

* Expected spatial dimensions.

* Empty output after unpadding.

* Allocation success for intermediate NCNN matrices.

Fix: Validate every intermediate tensor before accessing its memory. Reject unexpected model output instead of continuing with assumptions.

6. RealSR: bitmap processing has exception-safety gaps

File: `realsr_jni.cpp`, approximately lines 890–1128.

The adaptive detail enhancement and Lanczos4 functions allocate substantial `std::vector` buffers.

These allocations can throw `std::bad_alloc`. In these functions, allocation happens after bitmap pixels have been locked, without a surrounding cleanup guard.

An allocation failure can therefore:

* Leave the bitmap locked.

* Allow a C++ exception to escape across the JNI boundary.

* Potentially terminate the application.

Fix: Introduce RAII bitmap-lock guards and catch native allocation exceptions at every JNI entry point.

SECTION 2: COMPREHENSIVE ITEM-BY-ITEM MAPPING
--------------------------------------------------------------------------------
Mapping all 7 specific items identified in the audit and prompt:

1. [ITEM 1] PII Detector Missing Bitmap-Format & Dimension Validation
   - Subsystem: PII / Face Detection Native Bridge (`pii_ncnn_jni.cpp`)
   - Functions: `Java_com_veilframe_app_privacy_ncnn_PiiNcnnNative_nativeDetectFaces` and `Java_com_veilframe_app_privacy_ncnn_PiiNcnnNative_nativeDetectPii`
   - Problem: Neither method checks `info.format == ANDROID_BITMAP_FORMAT_RGBA_8888`. They also do not check for negative/zero dimensions (`orig_w <= 0 || orig_h <= 0`), 64-bit integer pixel overflow (`static_cast<uint64_t>(orig_w) * orig_h > MAX_PIXELS`), or null `pixels` after `AndroidBitmap_lockPixels`.
   - Risk: Interpreting RGB_565 or non-RGBA bitmaps as 4-byte RGBA leads to memory out-of-bounds reads, corrupted detections, or segfaults.

2. [ITEM 2] RIFE Unchecked Dimensions, Pixel Overflow, Timestep, and UTF String Acquisition
   - Subsystem: RIFE Frame Interpolation Native Bridge (`rife_jni.cpp`)
   - Functions: `Java_com_veilframe_app_media_rife_RifeNcnnNative_nativeInit` and `Java_com_veilframe_app_media_rife_RifeNcnnNative_nativeInterpolate`
   - Problem:
     * In `nativeInit`, `env->GetStringUTFChars(modelDir, nullptr)` return value is not checked before creating `std::string dir_str(dir_c)`. A null pointer causes undefined behavior/crash, and calling `ReleaseStringUTFChars` on null is unsafe.
     * In `nativeInterpolate`, `pixel_count = w * h` uses 32-bit signed integer arithmetic. Very large dimensions can overflow before casting to `size_t`.
     * `timestep` is passed directly without verifying `std::isfinite(timestep)` and `0.0f <= timestep && timestep <= 1.0f`.
   - Risk: Integer overflow buffer underruns, NaN/infinite timesteps causing model execution crashes or hangs, null pointer dereference during model directory resolution.

3. [ITEM 3] Uncoordinated Vulkan / NCNN GPU Instance Lifecycle
   - Subsystem: Shared NCNN / Vulkan GPU Subsystems (`rife_jni.cpp` and `realsr_jni.cpp` in `libveilframe_ncnn.so`)
   - Functions: `rife_jni.cpp` (`nativeInit`, `nativeRelease`), `realsr_jni.cpp` (`nativeGlobalInit`, `nativeGlobalDestroy`)
   - Problem: RIFE maintains its own static `g_rife_gpu_instance_created` flag and unconditionally calls `ncnn::destroy_gpu_instance()` inside `nativeRelease()`. RealSR manages its own lifecycle and also calls `ncnn::destroy_gpu_instance()`. If RIFE releases its engine while RealSR is holding GPU resources or running inference, NCNN's shared Vulkan context is destroyed beneath it.
   - Risk: Device lost errors, Vulkan driver crashes, invalid GPU handle crashes when multiple AI features are active in the same process.

4. [ITEM 4] Matting Unchecked JNI String Acquisition & Model Type Fallback
   - Subsystem: Background Matting Native Bridge (`matting_jni.cpp`)
   - Function: `Java_com_veilframe_app_cv_segmentation_ncnn_NcnnMattingNative_nativeInit`
   - Problem:
     * `param_c = env->GetStringUTFChars(paramPath, nullptr)` and `bin_c = env->GetStringUTFChars(binPath, nullptr)` are called without null checks. If the second fails, the first is leaked or dereferenced as null.
     * `modelType` is not validated against known constants (`MODEL_MODNET = 1`, `MODEL_U2NETP = 2`). Any arbitrary value other than 2 silently falls back to MODNet.
   - Risk: Process crash on null string, resource leak on partial JNI string acquisition, undefined behavior on invalid model type input.

5. [ITEM 5] Matting Missing Output & Intermediate Tensor Validation
   - Subsystem: Background Matting Native Bridge (`matting_jni.cpp`)
   - Function: `Java_com_veilframe_app_cv_segmentation_ncnn_NcnnMattingNative_nativeProcessBitmap`
   - Problem: After extraction, code assumes `out` and `out_unpadded` have valid dimensions, channel count >= 1, non-empty shapes, and non-null channel pointers before reading `out_unpadded.channel(0)` and iterating `out_unpadded.w * out_unpadded.h`. `alpha_full` after `resize_bilinear` is also assumed valid without verification.
   - Risk: Memory corruption or segfault if model fails to allocate output blobs or produces unexpected tensor shapes.

6. [ITEM 6] RealSR Bitmap Processing Exception-Safety Gaps & RAII Lock Guards
   - Subsystem: Super-Resolution Native Bridge (`realsr_jni.cpp`)
   - Functions: `Java_com_veilframe_app_upscale_inference_NcnnNative_nativeAdaptiveDetailEnhance` and `Java_com_veilframe_app_upscale_inference_NcnnNative_nativeScaleLanczos4`
   - Problem:
     * In both functions, `AndroidBitmap_lockPixels` is called before large `std::vector` buffers are allocated (`Y`, `blur_h`, `h_weights`, `v_weights`, `temp_buf`).
     * No RAII lock guard wraps the locked bitmap. If a vector allocation throws `std::bad_alloc`, the bitmap remains permanently locked in native memory and the C++ exception escapes across the JNI boundary to ART, crashing the app.
     * Missing dimension bounds checking on `targetW` and `targetH` in Lanczos4 can cause massive allocation attempts.
   - Risk: Bitmap memory leaks, unhandled C++ exceptions crossing JNI boundary causing SIGABRT.

7. [ITEM 7] Excel Spreadsheets Converted to PDF Causing Texts to Overlap Other Rows
   - Subsystem: Office Document Conversion Pipeline (`OfficeConverter.kt` and `OpenXmlDocumentParser.kt`)
   - Components: `OpenXmlDocumentParser.parseWorksheet`, `OfficeConverter.convertXlsxToPdf`, `wrapText`
   - Problem:
     * In `OpenXmlDocumentParser.parseWorksheet`, `<c r="C2">` column coordinate `r` is ignored when building rows. Skipped cells in sparse rows shift subsequent cells leftward into incorrect columns, corrupting column alignments, widths, and row structures.
     * In `OfficeConverter.kt`, `wrapText` replaces all whitespace including `\n` and `\r\n` with single spaces, collapsing user-defined multi-line paragraphs into single lines and failing to split long unbroken tokens.
     * Cells lack PDF graphics clipping (`contentStream.saveGraphicsState()`, `clip()`, `restoreGraphicsState()`), allowing any overflowing text or descenders to bleed across cell boundaries and overlap adjacent rows.
   - Risk: Unreadable PDF outputs, text overlapping across rows and columns, corrupted spreadsheet visual layout.

SECTION 3: INITIAL STEP-BY-STEP REMEDIATION PLAN
--------------------------------------------------------------------------------
1. Centralized GPU Lifecycle Management:
   - Create a shared C++ header `vulkan_gpu_lifecycle.h` in `android/app/src/main/cpp/`.
   - Maintain an atomic reference count `g_vulkan_gpu_ref_count` protected by a mutex `g_vulkan_gpu_mutex`.
   - Provide `acquire_gpu_instance()` returning a boolean indicating if Vulkan GPU instance is active.
   - Provide `release_gpu_instance()` which decrements the ref count and invokes `ncnn::destroy_gpu_instance()` only when ref count drops to zero.
   - Replace separate GPU creations/destructions in `rife_jni.cpp` and `realsr_jni.cpp`.

2. PII Detection Hardening (`pii_ncnn_jni.cpp`):
   - In `nativeDetectFaces` and `nativeDetectPii`:
     * Verify `srcBitmap != nullptr`.
     * Check `info.format == ANDROID_BITMAP_FORMAT_RGBA_8888`.
     * Check `orig_w > 0 && orig_h > 0`.
     * Enforce 64-bit bounds: `static_cast<uint64_t>(orig_w) * orig_h <= MAX_PIXELS`.
     * Use an RAII `BitmapPixelScope` to guarantee unlock on any exit.
     * Verify `pixels != nullptr` before calling `ncnn::Mat::from_pixels_resize`.

3. RIFE Bridge Hardening (`rife_jni.cpp`):
   - In `nativeInit`:
     * Validate `modelDir != nullptr`.
     * Acquire `dir_c` and check `dir_c != nullptr`.
     * If null, log error and return `JNI_FALSE`.
     * Release UTF chars cleanly.
     * Use centralized `acquire_gpu_instance()`.
   - In `nativeInterpolate`:
     * Validate `bitmap0` and `bitmap1`.
     * Validate dimensions `w > 0 && h > 0` and 64-bit overflow `static_cast<uint64_t>(w) * h <= MAX_PIXELS`.
     * Validate `std::isfinite(timestep)` and `0.0f <= timestep && timestep <= 1.0f`.
     * Use RAII bitmap unlock guards for both input bitmaps and output bitmap.
   - In `nativeRelease`:
     * Use centralized `release_gpu_instance()`.

4. Matting Bridge Hardening (`matting_jni.cpp`):
   - In `nativeInit`:
     * Validate `modelType == MODEL_MODNET || modelType == MODEL_U2NETP`.
     * Validate `paramPath != nullptr && binPath != nullptr`.
     * Check `param_c != nullptr`. If null, return `JNI_FALSE`.
     * Check `bin_c != nullptr`. If null, release `param_c` and return `JNI_FALSE`.
     * Release both strings cleanly before returning.
   - In `nativeProcessBitmap`:
     * Validate `out.empty() == false`, `out.dims >= 2`, `out.c >= 1`, `out.w > 0`, `out.h > 0`.
     * Validate `out_unpadded.empty() == false`, `out_unpadded.dims >= 2`, `out_unpadded.c >= 1`.
     * Verify `out_unpadded.channel(0) != nullptr`.
     * Verify `alpha_full.empty() == false && alpha_full.data != nullptr`.
     * Use RAII bitmap unlock guard for `maskBitmap`.

5. RealSR Exception Safety & RAII Guards (`realsr_jni.cpp`):
   - Implement `BitmapPixelScope` RAII struct for automatic unlocking.
   - In `nativeAdaptiveDetailEnhance`:
     * Bounds check `static_cast<uint64_t>(w) * h <= MAX_PIXELS`.
     * Acquire pixels with RAII guard.
     * Wrap vector allocations and enhancement logic in `try { ... } catch (const std::exception& e) { ... return JNI_FALSE; } catch (...) { return JNI_FALSE; }`.
   - In `nativeScaleLanczos4`:
     * Bounds check `targetW > 0 && targetH > 0` and `static_cast<uint64_t>(targetW) * targetH <= MAX_PIXELS`.
     * Wrap both source and destination bitmaps with RAII unlock guards.
     * Wrap allocations and filtering in `try { ... } catch (...) { return nullptr; }`.

6. Excel Spreadsheet Parser & PDF Converter Fix (`OpenXmlDocumentParser.kt` & `OfficeConverter.kt`):
   - In `OpenXmlDocumentParser.kt`:
     * Implement `colRefToIndex(ref: String): Int` to extract column letters from `<c r="C2">`.
     * Pad missing column cells with `""` up to the cell's target column index.
   - In `OfficeConverter.kt`:
     * Enhance `wrapText` to preserve `\n` and `\r\n` linebreaks.
     * Break long unbroken tokens that exceed `maxWidth`.
     * Enclose cell rendering in `saveGraphicsState()`, cell rect `clip()`, and `restoreGraphicsState()`.
     * Clamp `dynamicRowHeight` to printable page bounds to prevent page break loops.

SECTION 4: BROADER ARCHITECTURAL AND EDGE-CASE PLAN
--------------------------------------------------------------------------------
Broadening the plan to ensure zero blind spots across native memory, multithreading, and office fidelity:

A. Native Memory & Thread-Safety Matrix:
   - Max Pixel Cap: Standardize `MAX_PIXELS = 100000000ULL` (100 MP) across all bridges (`pii_ncnn_jni.cpp`, `rife_jni.cpp`, `realsr_jni.cpp`, `matting_jni.cpp`).
   - Unified `BitmapPixelScope`: Create a lightweight header `bitmap_scope.h` usable across all cpp files to prevent duplicate definitions and ensure uniform lock/unlock semantics.
   - Mutex Synchronization:
     * Ensure `g_vulkan_gpu_mutex` protects GPU reference counting across concurrent threads.
     * Keep existing engine-specific mutexes (`g_pii_mutex`, `g_rife_mutex`, `g_matting_mutex`, `g_lifecycle_mutex`) strictly scoped so they do not deadlock with the GPU lifecycle mutex.

B. JNI Exception Boundary Guarantees:
   - ART Specification: No C++ exception (`std::bad_alloc`, `std::runtime_error`, etc.) must EVER cross the JNI boundary into the Java/ART virtual machine. Uncaught C++ exceptions crossing JNI cause an uncatchable fatal abort (`SIGABRT`).
   - Every JNI exported entry point touched in this audit must catch `const std::bad_alloc&`, `const std::exception&`, and `(...)`, log the error, and return a clean failure indicator (`nullptr`, `JNI_FALSE`, or negative code).

C. Excel to PDF Visual Alignment & Edge Cases:
   - Column coordinate gaps: Handle both 1-letter (`A`..`Z`) and multi-letter (`AA`..`ZZ`) Excel column references.
   - Row skips: If sheet rows are non-consecutive (e.g. row 1, then row 5), maintain row continuity without crashing.
   - Cell padding & clipping: Ensure cell border line stroke is drawn AFTER or OUTSIDE the clip boundary so borders are crisp and text inside has clear 2pt margins without touching borders.
   - Font measurement safety: All `font.getStringWidth()` calls must be guarded against characters not present in WinAnsiEncoding (fallback to approximate width or sanitized text).

D. Verification Strategy:
   - Run unit tests for Office converter and OpenXML parsing.
   - Add new targeted tests for sparse column parsing and multi-line wrapping in `OpenXmlDocumentParserTest.kt` and `OfficeConverterFidelityTest.kt`.
   - Run native/JVM unit test suite via `.\gradlew.bat :app:testDebugUnitTest`.
