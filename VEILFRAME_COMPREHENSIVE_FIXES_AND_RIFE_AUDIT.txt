4. SECOND DEEPER & BROADER ARCHITECTURAL PLAN
--------------------------------------------------------------------------------
Broader Analysis & Edge-Case Hardening:
1. RIFE Memory Management & High-Frame Video Stress:
   - A 30-second 30fps video has ~900 source frames. With 2x interpolation, 1,800 frames are processed.
   - At 1080p, each uncompressed ARGB_8888 frame is ~8 MB. Holding even 20 frames in memory simultaneously will trigger an Android OOM (Out Of Memory) crash.
   - Architecture requirement: Ensure sequential producer-consumer pipeline:
     * Load pair (frame N, frame N+1) -> interpolate intermediate frame -> write immediately to disk JPEG/WebP -> recycle intermediate Bitmap immediately.
     * Keep persistent C++ buffers (`g_rgb0`, `g_rgb1`, `g_rgb_out`) statically sized across iterations so JNI allocations do not fragment the native heap.
     * Guard `RifeNcnnNative` calls with try/catch in `VeilFrameProcessingService.kt` to allow graceful fallback to optical flow if native memory is constrained.

2. Vulkan Device Compatibility Across Mobile Architectures:
   - Qualcomm Adreno vs ARM Mali vs PowerVR vs Android Studio ranchu/goldfish:
     * Adreno supports fp16 arithmetic and packed Vulkan storage well, but Mali devices often have strict alignment requirements for command buffer dispatch.
     * In `rife_jni.cpp`: catch any Vulkan error code in `rife->load()` or `rife->process()`. If GPU process fails mid-stream, switch runtime state to CPU OpenMP (`g_rife_gpuid = -1`), reload the CPU model, and continue without failing the user's video export job.

3. Spreadsheet Layout Fidelity in XLSX -> PDF:
   - Edge case: Spreadsheets with 15+ columns. If columns are equally squeezed, text wraps into hundreds of vertical lines.
   - Excel handles this by:
     a) Setting a sensible minimum column width (e.g., 40pt) and maximum column width (e.g., 200pt).
     b) Weighting column widths by character count: `colWeight = sqrt(maxCharInCol)`.
     c) Normalizing weights so the table spans the printable width of the A4 landscape page.
     d) If columns exceed printable width even at minimum size, allow clean horizontal page splitting or scaling factor.
     e) Page break handling: If a row with wrapped text exceeds remaining page height, break cleanly to next page without slicing text lines.

4. Mixed-Style Word Wrapping in DOCX -> PDF:
   - In DOCX, a single paragraph can have: "This is **very important** and must be *preserved*."
   - When wrapping lines:
     * The line breaker must measure words with the exact font for that word (`HELVETICA_BOLD` for bold, `HELVETICA` for regular).
     * If bold words are measured with regular font metrics, text will overrun the right margin and clip!
     * We implement a multi-run word wrapper: split text into tokens `(word, isBold, isItalic)`, accumulate tokens until line width exceeds `printableWidth`, then emit the line segments with their respective fonts.

5. Accessibility & Theme System Integrity:
   - The toggle buttons in Markdown Studio and mode selectors in Background Remover must maintain WCAG contrast ratios in both Light Theme and Dark Theme (`vf_theme_oled`).
   - Touch targets for all buttons must satisfy the 48x48dp minimum touch target requirement via `minHeight` or padding, even when visual height is compact (36dp).
