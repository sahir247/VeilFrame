Finding 1 — Matting bypasses shared Vulkan ownership.

`matting_jni.cpp` enables Vulkan based on `ncnn::get_gpu_count()`, but does not call `acquire_gpu_instance()` or `release_gpu_instance()`.

This is a real lifecycle inconsistency. RIFE and RealSR can correctly decrement the shared reference count to zero while a matting model still has Vulkan enabled. The manager cannot protect a subsystem that never registers its ownership.

Fix: integrate matting into the same lifecycle, or explicitly force matting to CPU until it has a safe shared-GPU ownership model. Track acquisition per model and release it when that model is replaced or released. Do not acquire repeatedly for an already-loaded model.

Finding 2 — RIFE initialization leaks a GPU reference on model-load failure.

In `rife_jni.cpp`, GPU acquisition occurs before `g_rife->load(dir_str)`. If loading fails, the function deletes the RIFE object and returns `JNI_FALSE`, but does not release the acquired GPU reference or clear `g_rife_gpu_instance_created`.

The reference is eventually released if another init or explicit release happens. Until then, the shared instance remains unnecessarily retained.

Fix: use a rollback guard for the acquired reference and commit ownership only after successful initialization. Also handle exceptions around the entire init function.

Finding 3 — JNI exception containment is still incomplete.

The code has catch blocks in RIFE inference and several RealSR operations, but the following paths remain exposed:

* `PiiNcnnNative.nativeInit`

* `PiiNcnnNative.nativeDetectFaces`

* `PiiNcnnNative.nativeDetectPii`

* `NcnnMattingNative.nativeInit`

* `NcnnMattingNative.nativeProcess`

* `NcnnMattingNative.nativeProcessLegacy`

* `RifeNcnnNative.nativeInit`

These paths allocate objects and vectors, perform inference, or invoke JNI reflection. A C++ exception must not escape a JNI boundary.

Fix: add exception containment to every exported JNI entry point, not only the most recently modified ones. Ensure partially initialized models and acquired resources are rolled back correctly.

Finding 4 — PII tensor parsing needs stricter validation.

The PII detector checks that output tensors are nonempty, but its YOLOv8 decoder makes assumptions about output layout and feature count. In particular, the fallback branch uses `num_anchors = out.h` and `total_features = out.w` without first proving that the dimensions match a supported model output.

The code also accepts caller-provided score and IoU thresholds without checking that they are finite or within sensible ranges.

Fix: validate supported tensor shapes and data layout before decoding; reject invalid thresholds and non-finite model outputs. Validate the final array length before converting it to `jsize`.

Finding 5 — Legacy matting remains a weaker path.

`nativeProcessLegacy` has bitmap format and dimension validation, and uses the new bitmap scope. But it still uses the older direct-stretch preprocessing and legacy mask generation path, with no enclosing exception handler.

This is not necessarily a functional defect if the legacy method is intentionally retained, but it is still a separate native entry point that needs the same safety guarantees as the main path.

Fix: either remove the legacy entry point if unused, or bring it up to the same validation, exception and lifecycle standards.

### 2. Shared Vulkan manager

`vulkan_gpu_lifecycle.h` is a meaningful improvement: the reference count is protected by a mutex, and destruction occurs when the count reaches zero.

But there are two design improvements I would make:

* Use an ownership token/RAII lease instead of manually paired acquire/release calls. This makes it harder to leak a reference on early returns.

* Guard against reference-count overflow and make initialization state explicit. A simple integer count does not distinguish a successfully initialized instance from a failed or partially initialized one.

The manager also needs a concurrency test that exercises RIFE and RealSR initialization, inference and teardown at the same time. A mutex around the counter alone does not prove that every subsystem has stopped using Vulkan before the final release.

### 3. XLSX parser and PDF conversion

The original sparse-column defect is addressed: `colRefToIndex()` supports multi-letter columns, and `parseWorksheet()` inserts empty cells for missing columns.

However, I found another parser issue.

Finding 6 — Explicit worksheet row numbers are ignored.

`parseWorksheet()` reads each row element but never uses its `r` attribute. It appends only rows containing nonblank values.

For example, if an XLSX sheet contains row 1 and row 5, the parser returns them as adjacent rows. Blank rows and their original positions are lost. This can change the layout and meaning of spreadsheets that use blank rows as section separators.

Fix: use the row number attribute to preserve row positions, inserting empty rows where necessary. Also test cells whose references are missing or malformed.

Finding 7 — PDF row-height clamping can hide content.

The renderer calculates a dynamic height, then clamps it to `maxPrintableHeight`. It clips text to the cell, which prevents text from bleeding into adjacent cells. But when the required wrapped text is taller than the clamped row, the remaining lines are clipped away.

That prevents overlap, but does not guarantee content preservation.

Fix: split exceptionally tall rows across pages, or explicitly mark the cell as truncated and provide a continuation. Do not silently clip content while describing the conversion as lossless.

Finding 8 — The PDF fidelity tests do not yet prove layout fidelity.

The new tests are useful regression smoke tests, but they mostly assert:

* PDF exists and is nonempty.

* Page count is one.

* Page orientation is landscape.

They do not inspect extracted text positions or verify that text remains within its intended cell. Nor do they test a row taller than the printable page, multiple-page output, or blank worksheet rows.

Fix: add PDF text-position assertions using PDFBox text extraction with coordinates, and add fixtures for multi-page tables, very long cells, explicit newlines, blank rows and sparse columns.

SECTION 4: BROADER ARCHITECTURAL, CONCURRENCY & EDGE-CASE PLAN
--------------------------------------------------------------------------------
A. Vulkan Concurrency & Multi-Subsystem State Machine:
   - When RIFE, RealSR, and Matting run concurrently or in interleaved order:
     * Every subsystem holds a `GpuInstanceLease`.
     * `g_gpu_mutex` serializes all ref-count mutations and Vulkan instance creation/destruction.
     * Destruction can NEVER occur while any of the three subsystems holds an active lease.
   - Subsystem-specific mutexes (`g_rife_mutex`, `g_matting_mutex`, `g_pii_mutex`, `g_lifecycle_mutex`) must be acquired independently of `g_gpu_mutex` to prevent deadlock.

B. Zero-Exception Leak Across JNI Boundary:
   - Under Android ART, an uncaught C++ exception escaping across an `extern "C"` JNI function causes a fatal `SIGABRT`.
   - Every single entry point must guarantee:
     1. All C++ operations occur within `try { ... } catch (...)`.
     2. All allocated intermediate native objects (`new ncnn::Net`, `RIFE*`, `jobject`, etc.) are freed or rolled back on failure.
     3. Bitmaps locked via `BitmapPixelScope` are automatically unlocked before function returns.

C. Spreadsheet Structure & Coordinate System:
   - Excel OpenXML permits sparse columns (`<c r="C2">`) AND sparse rows (`<row r="10">`).
   - Coordinate parsing must handle:
     * Missing columns (e.g. A and D only -> B and C are empty).
     * Missing rows (e.g. 1 and 5 only -> 2, 3, 4 are empty).
     * Non-standard or missing `r` attribute (fallback to sequential order).
     * Empty cells with style/type tags but no value.

D. Complete Lossless PDF Document Fidelity:
   - Cell bounding-box clipping prevents overlap into neighbor cells.
   - Multi-page pagination prevents clipping away vertical overflow.
   - Long unbroken tokens (e.g. URLs, hashes) are wrapped by character chunks.
   - Newline characters (`\r\n`, `\n`) are preserved as explicit linebreaks.
   - Font measurement handles special characters with WinAnsi fallback to avoid exceptions.
