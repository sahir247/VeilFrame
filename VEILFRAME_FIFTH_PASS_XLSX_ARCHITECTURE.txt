SECTION 2: EXHAUSTIVE REQUIREMENT MAPPING AND GAP ANALYSIS
================================================================================
1. ASYMMETRY IN PAGE BOUNDS & PDF COORDINATE LIMITS:
   - Root Cause: In OfficeConverter.kt, `pageHeight` was capped at `maxPdfPageHeight = 14400f`, but `pageWidth` was computed as `maxOf(minPageWidth, totalTableWidth + 2 * margin)` with zero upper bound. A spreadsheet with 200 wide columns (e.g. 20,000 pt total width) produced a single page exceeding ISO 32000-1 coordinate limits (14,400 pt = 200 inches @ 72 dpi), causing Acrobat and mobile PDF viewers to fail or truncate.
   - Gap: Need explicit upper bounds for both width and height, and a strategy selector that gracefully transitions when limits are exceeded.

2. SPREADSHEET LAYOUT ENGINE & GEOMETRY MODEL:
   - Gap: Currently, layout calculations (column widths, wrapped lines, row heights, coordinates) are embedded directly inside the PDF drawing loop in OfficeConverter.kt.
   - Requirement: Extract geometry into a reusable `SpreadsheetLayoutEngine` and data model:
     * `SpreadsheetLayout`: contains `SheetLayout` per sheet.
     * `SheetLayout`: column widths, column start X positions, pre-calculated row wrapped cell lines, row heights, row start Y positions, merged cell ranges, total table width, total table height.
     * Geometry extraction is clean, testable independently of PDFBox rendering, and reusable across all export strategies.

3. EXPORT STRATEGY SELECTOR:
   - Requirement: An explicit strategy selector deciding between:
     * `ExportStrategy.NATURAL_SIZE` (Level 1): Natural content-sized single page when both `totalWidth <= maxPageWidth` (14,400 pt) and `totalHeight <= maxPageHeight` (14,400 pt).
     * `ExportStrategy.EXTENDED_SIZE` (Level 2): Single extended-size page using `/UserUnit = U` when natural dimensions exceed 14,400 pt (up to 75,000 pt). By setting `/UserUnit = U` (where U = max(ceil(totalWidth / 14400), ceil(totalHeight / 14400))) and scaling coordinates by `1 / U`, physical font sizes and line weights remain visually constant while PDF coordinates remain strictly within the 14,400 pt limit.
     * `ExportStrategy.TILED` (Level 3): Lossless two-dimensional tile planner when dimensions exceed Level 2 limits or when tiling is explicitly requested or preferred for extreme sheets. Preserves horizontal column order and vertical row order in row-major tile sequence.

4. LEVEL 1 IMPLEMENTATION (NATURAL SIZE):
   - Single content-sized page with strict validation that BOTH width <= 14,400 pt and height <= 14,400 pt.
   - Respects minPageWidth (842 pt) and minPageHeight (595 pt) for small spreadsheets.
   - Dynamic expansion without squishing.

5. LEVEL 2 IMPLEMENTATION (EXTENDED SIZE VIA /UserUnit):
   - ISO 32000-1 compliant `/UserUnit` dictionary entry on `PDPage`.
   - Scale factor `U = max(totalWidth / maxCoord, totalHeight / maxCoord).coerceAtLeast(1f)`.
   - Page dimensions set to `(totalWidth / U, totalHeight / U) <= 14400f`.
   - Coordinate transform applied to page content stream (or inverse scaling of coordinates and fonts) such that rendered points in user space match visual intent.
   - Tested and verified against PDF readers.

6. LEVEL 3 IMPLEMENTATION (LOSSLESS 2D TILED PDF):
   - 2D tile planner partitioning columns into horizontal panels (column groups) and rows into vertical panels (row groups).
   - Strict row-major sequence:
     Row Group 1:
       Column Group 1 (Leftmost, columns A–AD)
       Column Group 2 (Next, columns AE–BH)
       ...
     Row Group 2:
       Column Group 1
       Column Group 2
       ...
   - Continuation Headers and Navigation:
     * Panel header banner: "Sheet: {name} | Rows {rStart}–{rEnd} | Columns {cStart}–{cEnd} | Panel {colIdx+1} of {totalCols}"
     * Right continuation banner: "Continues right → {nextCol}"
     * Left continuation banner: "Continued from {prevCol} ←"
     * Down continuation banner: "Continues down ↓ Row {nextRow}"
   - Optional Frozen Column Repetition: Repeating key identifying columns (e.g. Column A / ID column) on each horizontal panel to preserve row context across horizontally paginated panels.
   - Merged Cells across tile boundaries: Graceful clipping and continuation without visual corruption or overlapping text.
   - Extremely wide individual cells: Handled cleanly without silent truncating.

7. UNIFIED DRAWING PIPELINE:
   - Reuse the exact same cell drawing, clipping, text wrapping, and styling code across all three strategies (Level 1, Level 2, Level 3).

8. COMPREHENSIVE TEST SUITE REQUIREMENTS:

SECTION 4: BROADER ARCHITECTURAL AND EDGE-CASE RESILIENCE PLAN
================================================================================
1. Coordinate Ceilings & Overflow Resilience:
   - PDF coordinate limits (14,400 pt) are hard limits in PDF specification (ISO 32000-1 Annex C.2). Exceeding this without `/UserUnit` creates corrupted or unopenable PDFs in Adobe Acrobat, iOS PDF viewer, and Android PdfRenderer.
   - When UserUnit is applied, `U` must be an integer or clean float between 1.0 and 75,000 / 14,400 = 5.2x (ISO 32000-1 allows UserUnit up to 75,000, which extends coordinate space up to 75,000 pt).
   - If a sheet exceeds 75,000 pt in either dimension, Level 2 must safely fall back to Level 3 (Tiled).

2. 2D Tiling Sequence & Mental Model:
   - When printing or viewing large tiled sheets, users read left-to-right, then top-to-bottom. Row-major panel sequence ensures that reading Row 1..100 across columns A..Z, then AA..AZ, etc., follows natural spreadsheet reading order.
   - Continuation banners must explicitly identify:
     * Sheet name
     * Row interval (e.g., Rows 1–100)
     * Column interval (e.g., Columns A–AD)
     * Panel index (e.g., Panel 1 of 4)
     * Directional pointers: `Continues right → Col AE`, `Continued from ← Col AD`, `Continues down ↓ Row 101`.

3. Frozen Identifying Columns:
   - In horizontally split spreadsheets, viewing column ZZ without column A (which typically contains the Row ID, Name, or Key) makes the data incomprehensible.
   - Providing an option to repeat frozen columns (e.g., Column 0 / A) on each horizontal panel ensures immediate context preservation.

4. Cell ID Integrity Validation:
   - Standard PDF text extractors can flatten or skip text if bounding boxes are inconsistent.
   - Every cell should carry a distinct verifiable token (e.g. `[R{row}_C{col}_V]`).
   - The test must extract all tokens across all pages, assert `set(extracted) == set(expected)`, and assert `extracted.size == expected.size` (0 duplicates, 0 dropped).

5. Single Column Exceeding Tile Width:
   - If an individual column width alone exceeds `maxTileWidth` (e.g., a massive text dump cell > 14,400 pt), the layout engine must clamp or tile the cell width gracefully so it does not crash the planner with an infinite loop.

6. Empty and Blank Rows/Columns Handling:
   - Ensure sheets with trailing empty cells, sparse rows, or blank headers do not produce blank pages or NaN widths.
