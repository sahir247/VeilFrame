### New findings from this pass

1\. Privacy verification still fails open

High

[`PrivacyVerification.kt`](https://github.com/sahir247/VeilFrame/blob/main/android/app/src/main/java/com/veilframe/app/privacy/PrivacyVerification.kt?utm_source=chatgpt.com)

`verifyImage()` catches metadata-reading exceptions and continues. If the file exists but cannot be parsed, it can return `isClean = true` because no tags were added to the results.

The checker also inspects only selected EXIF fields. It does not establish that every potentially identifying metadata field or container-level metadata block has been removed.

Fix: distinguish `CLEAN`, `NOT_CLEAN`, and `VERIFICATION_FAILED`. A parsing failure must never produce a clean result.

2\. Background-removal model downloads can report success with an incomplete model

High

[`RembgModelDownloadManager.kt`](https://github.com/sahir247/VeilFrame/blob/main/android/app/src/main/java/com/veilframe/app/cv/segmentation/rembg/RembgModelDownloadManager.kt?utm_source=chatgpt.com)

The model binary is installed before the separate `.param` file is downloaded. The helper `downloadSimpleFile()` catches download failures without propagating them, and the outer operation can still invoke `onSuccess()` and return `Result.success()`.

The MODNet model definition also leaves its SHA-256 checksum empty, making the binary's checksum verification conditional rather than mandatory. The helper follows redirects automatically, unlike the primary download path, which explicitly validates redirect destinations.

Fix: download both files to temporary paths, validate both, and install the pair only after all checks pass. Reject unexpected redirects and require pinned checksums for both artifacts.

3\. Image sanitization can report success without checking the encoder result

Medium

[`ImageMetadataSanitizer.kt`](https://github.com/sahir247/VeilFrame/blob/main/android/app/src/main/java/com/veilframe/app/privacy/ImageMetadataSanitizer.kt?utm_source=chatgpt.com)

Both `reencodePixels()` and `sanitizeFromUri()` call `Bitmap.compress()` but ignore its Boolean return value. They then treat a nonempty output file as success. If compression returns `false` while leaving nonempty output, the function can claim success for an invalid or incomplete result.

Also, `hasIdentifiableMetadata()` returns `false` if metadata parsing throws. That means “could not inspect” is indistinguishable from “no identifiable metadata found.”

Fix: check the compression return value, clean up failed output files, and return an explicit unknown/error state when verification fails.

4\. Custom NCNN ZIP imports lack extraction limits

Medium

[`UpscaleModelRepository.kt`](https://github.com/sahir247/VeilFrame/blob/main/android/app/src/main/java/com/veilframe/app/upscale/model/UpscaleModelRepository.kt?utm_source=chatgpt.com)

`importCustomNcnnFromZip()` extracts archive entries into cache without a maximum expanded size, entry count, or per-entry limit. Flattening entry names avoids a basic path traversal issue, but it does not prevent a malicious or malformed archive from consuming excessive disk space.

Fix: enforce limits on total expanded bytes, individual files, and entry count; reject malformed or oversized archives before model import.

2. COMPREHENSIVE MAPPING & CODE INVENTORY
--------------------------------------------------------------------------------

[Finding 1] Privacy Verification Fails Open on Metadata Parsing Exceptions
- Affected File: `android/app/src/main/java/com/veilframe/app/privacy/PrivacyVerification.kt` (lines 17-53)
- Root Cause:
  1. In `verifyImage(file: File)`:
     ```kotlin
     try {
         val exif = ExifInterface(file.absolutePath)
         ...
     } catch (_: Exception) {}
     return ImagePrivacyReport(
         isClean = found.isEmpty() && !hasGps,
         foundTags = found,
         hasGps = hasGps
     )
     ```
     When `ExifInterface` throws an exception (e.g. malformed container, truncated header, I/O error), `found` remains empty and `hasGps` is false. The function concludes `isClean = true`. This is a classic "fail open" security defect.
  2. The check only tests 8 specific tags + GPS, leaving other identifiable EXIF, XMP, or MakerNote fields uninspected, yet claims a blanket `isClean = true`.
- Requirements for Resolution:
  1. Introduce an explicit enum `PrivacyStatus`: `CLEAN`, `NOT_CLEAN`, `VERIFICATION_FAILED`.
  2. If file reading or parsing throws any exception, status MUST be `VERIFICATION_FAILED` and `isClean` MUST be `false`.
  3. Expand inspection to scan `ImageMetadataSanitizer.ALL_EXIF_TAGS` (all standard EXIF tags, GPS tags, XMP, MakerNotes, user comments, serial numbers).
  4. Provide detailed error reporting when verification fails so callers never mistake unparseable files for sanitized files.

[Finding 2] Rembg Model Download Can Report Success with Incomplete / Missing .param File
- Affected Files:
  * `android/app/src/main/java/com/veilframe/app/cv/segmentation/rembg/RembgModelDownloadManager.kt` (lines 160-235)
  * `android/app/src/main/java/com/veilframe/app/cv/segmentation/rembg/RembgModel.kt` (lines 35-55)
- Root Cause:
  1. Non-Transactional Installation: In `downloadModel()`, the model binary (`.bin`) is atomically moved to `destFile` in production storage BEFORE the separate `.param` file is downloaded.
  2. Swallowed Secondary Download Failures: The helper `downloadSimpleFile(model.paramDownloadUrl, paramDest)` catches `Exception` and logs a warning without rethrowing or returning a status.
  3. False Success Reporting: `downloadModel()` then executes `listener?.onSuccess(model, destFile)` and returns `Result.success(destFile)`, leaving the app with an orphaned `.bin` file without its matching `.param` file. Subsequent inference crashes with NCNN param loading failure.
  4. Insecure Redirect Handling: `downloadSimpleFile` configures `conn.instanceFollowRedirects = true`, completely bypassing the origin allowlist check (`isAllowedModelUrl`) and allowing arbitrary third-party redirects.
  5. Missing Checksums: `MODNET` in `RembgModel.kt` declares `sha256 = ""` and lacks a `paramSha256` field, making checksum validation optional rather than mandatory.
- Requirements for Resolution:
  1. Transactional Staging: Download BOTH `.bin` and `.param` to isolated `.part` temporary files.
  2. Mandatory Checksum Verification: Pin and enforce SHA-256 checksums for both the `.bin` and `.param` files. If either fails checksum or download, discard both temporary files and fail the operation.
  3. Redirect Safety: Unify redirect handling using safe, manual redirect following that validates every redirect target against `isAllowedModelUrl()`.
  4. Atomic Dual-Installation: Only when both files have been completely downloaded, size-checked, and checksum-verified are they atomically moved into `repository.modelsDir`.

[Finding 3] Image Sanitization Ignores Bitmap.compress() Return Code
- Affected File: `android/app/src/main/java/com/veilframe/app/privacy/ImageMetadataSanitizer.kt` (lines 222-235, 248-266, 271-282)
- Root Cause:
  1. `reencodePixels()` and `sanitizeFromUri()` call `bmp.compress(format, quality, fos)` without inspecting the returned `Boolean`.
  2. The code then checks `outputFile.exists() && outputFile.length() > 0L`. If the underlying image encoder failed midway (e.g. out of memory, bad color profile, unsupported dimension), but flushed partial bytes, the functions report `true` (success) for a corrupted or incomplete image file.
  3. In `hasIdentifiableMetadata()`, `catch (_: Exception) { false }` returns `false` if `ExifInterface` fails, conflating "verification error" with "clean".
- Requirements for Resolution:
  1. In `reencodePixels()` and `sanitizeFromUri()`, store the return value of `bmp.compress()`.
  2. If `compress()` returns `false`, immediately delete the output file and return `false`.
  3. Flush and close the stream before verifying file size.
  4. In `hasIdentifiableMetadata()`, return a tri-state result or throw on failure so callers can distinguish between clean, dirty, and unparseable states.

[Finding 4] Custom NCNN ZIP Model Import Lacks Decompression Limits (Zip Bomb Vulnerability)
- Affected File: `android/app/src/main/java/com/veilframe/app/upscale/model/UpscaleModelRepository.kt` (lines 145-185)
- Root Cause:
  1. `importCustomNcnnFromZip()` loops through `ZipInputStream` entries and copies bytes directly to disk via `zis.copyTo(fos)` without bounds checking.
  2. Missing Security Limits:
     - No limit on total extracted bytes (decompression bomb / disk filling attack).
     - No limit on individual file size.
     - No limit on maximum entry count.
  3. Malformed Archives: An archive with hundreds of thousands of small entries or a recursive compressed stream can exhaust disk space, file descriptors, or trigger an OutOfMemoryError.
- Requirements for Resolution:
  1. Define strict extraction bounds:
     - `MAX_ENTRIES = 20` (NCNN models only need a `.param` and `.bin`, plus optional license/readme).
     - `MAX_SINGLE_FILE_BYTES = 250 * 1024 * 1024L` (250 MB).
     - `MAX_TOTAL_EXTRACTED_BYTES = 400 * 1024 * 1024L` (400 MB).
  2. Track cumulative bytes extracted and entry counts during stream consumption. If any threshold is breached, abort extraction, clean up temp directory, and throw `SecurityException`.
  3. Validate entry names to prevent directory traversal or reserved characters.

3. INITIAL REMEDIATION PLAN
--------------------------------------------------------------------------------

Step 1: Harden PrivacyVerification.kt
- Introduce `PrivacyVerification.VerificationStatus` enum: `CLEAN`, `NOT_CLEAN`, `VERIFICATION_FAILED`.
- Update `ImagePrivacyReport`:
  ```kotlin
  data class ImagePrivacyReport(
      val status: VerificationStatus,
      val isClean: Boolean, // helper: status == VerificationStatus.CLEAN
      val foundTags: List<String>,
      val hasGps: Boolean,
      val failureReason: String? = null
  )
  ```
- Scan all critical tags and `ImageMetadataSanitizer.ALL_EXIF_TAGS`.
- If an exception occurs, set `status = VerificationStatus.VERIFICATION_FAILED`, `failureReason = e.message`, and `isClean = false`.

Step 2: Harden RembgModel.kt & RembgModelDownloadManager.kt
- In `RembgModel.kt`:
  * Add `paramSha256` property to `RembgModel` enum.
  * Pin SHA-256 for `MODNET` `.bin` and `.param` artifacts.
- In `RembgModelDownloadManager.kt`:
  * Rewrite `downloadModel()` to execute a two-stage transactional pipeline:
    Stage A: Download `.bin` artifact to `model.bin.part` with origin check, redirect validation, and checksum verification.
    Stage B: Download `.param` artifact to `model.param.part` with matching origin check, redirect validation, and checksum verification.
  * If either download or verification fails, delete both `.part` files and abort with `Result.failure()`.
  * Atomically rename both `.part` files into `destFile` and `paramDest` only after both are verified.
  * Remove unsafe `downloadSimpleFile` implementation.

Step 3: Harden ImageMetadataSanitizer.kt
- In `reencodePixels()`:
  * Capture `val success = bmp.compress(...)`.
  * If `!success`, delete `outputFile` and return `false`.
  * Validate `outputFile.exists() && outputFile.length() > 0L`.
- In `sanitizeFromUri()`:
  * Capture `val success = bmp.compress(...)`.
  * If `!success`, delete `outputFile` and return `false`.
- In `hasIdentifiableMetadata()`:
  * If `ExifInterface` throws an error, do NOT return `false`. Return `true` (unsafe/unverified) or propagate status so unreadable images are never treated as clean.

Step 4: Harden UpscaleModelRepository.kt
- In `importCustomNcnnFromZip()`:
  * Define `MAX_ZIP_ENTRIES = 20`, `MAX_SINGLE_FILE_BYTES = 250 * 1024 * 1024L`, `MAX_TOTAL_BYTES = 400 * 1024 * 1024L`.
  * Read entries chunk by chunk with running byte counter.
  * Check for zip-slip / path traversal.
  * Abort and purge temp files if limits are exceeded.
