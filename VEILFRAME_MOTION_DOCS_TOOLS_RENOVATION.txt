[Item 1] App crashing when running Motion Lab with model (download successful)
- Affected Files:
  * android/app/src/main/cpp/rife/rife.cpp (lines 785-786, lines 3241-3242)
  * android/app/src/main/cpp/rife_jni.cpp (lines 57-86, lines 198-204)
  * android/app/src/main/java/com/veilframe/app/media/rife/RifeNcnnNative.kt
  * android/app/src/main/java/com/veilframe/app/media/MotionLabController.kt
  * android/app/src/main/java/com/veilframe/app/VeilFrameProcessingService.kt (lines 516-533, 601-625)
- Root Causes:
  1. Vulkan Allocator Double-Reclaim: In `rife.cpp`, `VkAllocatorScope` RAII helper was added to guard `blob_vkallocator` and `staging_vkallocator`. However, the bottom of `process()` (lines 785-786) and `process_v4()` (lines 3241-3242) still manually invoked `vkdev->reclaim_blob_allocator(blob_vkallocator)` without nulling the pointers. When `VkAllocatorScope` destructor fired at function exit, it reclaimed the same allocators a second time, triggering fatal NCNN heap memory corruption or SIGSEGV.
  2. Android Emulator Vulkan Incompatibility: In Android Studio emulator environments (ranchu/goldfish hardware), Vulkan compute via SwiftShader/host passthrough advertises Vulkan 1.1+ support, causing `ncnn::get_gpu_count()` to report 1 and `load()` to pass. However, executing compute shaders (especially 16-bit float/storage pipelines) crashes the emulator's Vulkan driver with a native SIGSEGV.
  3. Lack of Runtime GPU-to-CPU Fallback: If `nativeInterpolate()` fails on GPU during inference, it does not dynamically recover using CPU threads, leading to failed frames or pipeline aborts.

[Item 2] XLSX to PDF gives "org.apache.poi.xssf.usermodel.XSSFWorkbook" popup and does not convert
- Affected Files:
  * android/app/src/main/java/com/veilframe/app/pdf/operations/OfficeConverter.kt (lines 685-740)
  * android/app/src/main/java/com/veilframe/app/pdf/PdfQuickToolController.kt (lines 896-925, 2265, 2288-2306)
- Root Causes:
  1. Apache POI `poi-ooxml` runtime failure on Android: On Android ART runtime, `org.apache.poi.xssf.usermodel.XSSFWorkbook` fails with `NoClassDefFoundError` / `ClassNotFoundException` due to Java AWT, StAX XML, or XMLBeans class loading incompatibilities not supported by the Android Dalvik/ART runtime.
  2. In `OfficeConverter.kt`, `convertXlsxToPdf()` attempts `XSSFWorkbook(xlsxStream)` directly without an offline fallback. When ART throws `NoClassDefFoundError: org.apache.poi.xssf.usermodel.XSSFWorkbook`, it bubbles to `PdfQuickToolController.kt:2288`:
     `catch (t: Throwable) { conversionError = t.message }`
     which evaluates to `"org.apache.poi.xssf.usermodel.XSSFWorkbook"`.
  3. `Toast.makeText(..., conversionError, Toast.LENGTH_LONG).show()` pops up with this exact class name and halts conversion.
  4. Preview in `PdfQuickToolController.kt:901` also calls `XSSFWorkbook(stream)`, failing to generate spreadsheet previews.

4. SECOND DEEPER & BROADER ARCHITECTURAL PLAN (EDGE CASES & HOLISTIC CHECKS)
--------------------------------------------------------------------------------

Broader Consideration A: Memory Management & Bitmap Recycling in OpenXML Parsers
- High-resolution spreadsheets or 100-page DOCX files could generate large numbers of PDF pages.
- Memory budget rule: Render page by page, streaming to disk cache or using `MemoryUsageSetting.setupTempFileOnly()` in PDFBox.
- Avoid holding huge in-memory DOMs; parse XML sequentially with `XmlPullParser`.

Broader Consideration B: XML Entity Escaping & Encoding in DOCX/XLSX
- XML attributes and text nodes can contain `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`, numeric entities (`&#x...;`), and whitespace preserving flags (`xml:space="preserve"`).
- Our custom parser must decode all standard entities and respect explicit spaces between runs so words don't run together (e.g., `<w:t xml:space="preserve"> hello </w:t>`).

Broader Consideration C: Coroutine Cancellation across Document Conversions
- When converting large spreadsheets or documents, ensure `ensureActive()` is checked at the start of each row, paragraph, and page.
- Catch `CancellationException` and rethrow immediately to prevent zombie threads.

Broader Consideration D: Emulator Detection Robustness
- Android emulators vary: QEMU, Cuttlefish, BlueStacks, LDPlayer, Google APIs system images.
- Check `Build.FINGERPRINT`, `Build.MODEL`, `Build.HARDWARE`, `Build.MANUFACTURER`, and `Build.PRODUCT` for emulator signatures. If any match, disable NCNN Vulkan compute and use OpenMP CPU threads.

Broader Consideration E: Unit & Regression Testing
- Create automated unit tests for:
  1. OpenXML XLSX parsing and PDF generation (validating table structure and non-POI execution).
  2. OpenXML DOCX parsing with headings and text run formatting.
  3. Quick file intake document MIME type resolution and suggested tool wiring.
  4. BG Remover trim transparency state preservation.
