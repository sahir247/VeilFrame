I checked the current main commit, its diff, the XLSX-to-PDF implementation, the regression tests, and the third-pass audit report.

The previous assessment was a little too generous. The architectural direction is good, but I found some issues that should be fixed before considering this conversion path finished.

### 1. Findings

P2 — Default page height is accidentally 842 pt

Bug

Current code:

val pageHeight = minOf(
    maxPdfPageHeight,
    maxOf(PDRectangle.A4.width, totalRequiredHeight)
)

PDRectangle.A4.width is approximately 842 pt. The comment and audit report say the minimum should be 595 pt, but the implementation uses the width of A4 instead of its height.

This explains why the updated 60-line test expects a page taller than 650 pt.

Recommendation: If the intended minimum is A4 landscape height, use PDRectangle.A4.height. Keep the dynamic expansion above that minimum.

P2 — The 60-line test no longer tests pagination

Coverage regression

The previous test expected an oversized row to paginate across multiple pages. The new version expects exactly one page.

That is reasonable for a 60-line row whose content fits below 14,400 pt. But it removes the previous test's coverage of the pagination branch.

The implementation still has code to split oversized rows into chunks and continue on subsequent pages. That path now needs its own regression test.

Recommendation: Keep both tests:
* 60 lines fit on one dynamically expanded page.
* A row exceeding the page-height limit is split across pages without losing or duplicating lines.

P2 — The wide-column test proves only partial fidelity

Coverage gap

The new 25-column test checks:
* Page width exceeds 2,000 pt.
* First header is extractable.
* Last header is extractable.

It does not establish that all intermediate columns are present, correctly positioned, or non-overlapping.

Recommendation: Use the existing PositionalTextExtractor to assert all 25 headers, their increasing X coordinates, and their bounds relative to the page width.

P3 — Empty lines inside cells are collapsed

Minor fidelity issue

wrapText() splits text on newline characters, but skips empty paragraphs:

if (word.isEmpty()) continue

A cell containing First line\n\nThird line loses the blank line between the paragraphs.

This is not data loss in the sense of losing the text itself, but it does alter the original formatting.

Recommendation: Preserve empty paragraphs as empty output lines, while continuing to handle long unbroken tokens.

### 2. One inconsistency in the audit report

The third-pass report describes the oversized-row test as asserting multi-page pagination. The actual committed test now asserts:

assertEquals(1, doc.numberOfPages)

That report section is stale relative to the implementation.

The report also describes a 595 pt minimum page height, while the committed code uses PDRectangle.A4.width (842 pt).

These are documentation inconsistencies, not necessarily runtime defects, but they should be corrected. An audit report should describe the exact committed source and tests.

### 3. What is working well

I don't want to overlook the improvements:
* Column scaling has been removed.
* Column widths are calculated from content.
* Explicit newline handling and long-token splitting are present.
* Cell graphics clipping is retained.
* Row heights are calculated before rendering.
* Oversized rows still have a chunk-based pagination path.
* PDF document and content-stream cleanup is handled in finally.
* The 25-column and 60-line regression tests are now present.

The fundamental design is substantially better than forcing all spreadsheets onto A4.

### VeilFrame — XLSX-to-PDF implementation plan
Architecture proposal: Three-level export

Objective: Preserve spreadsheet content, natural dimensions, column order and readability without forcing the output into A4, A5 or another conventional paper size.

1. Target architecture
Separate layout calculation, export strategy selection and PDF rendering:
- XLSX parser: Cells, coordinates, styles, merged ranges
- Spreadsheet layout engine: Natural column widths, row heights, wrapping, total dimensions
- Export strategy selector: Level 1 (Natural size), Level 2 (Extended size via UserUnit), Level 3 (Tiled pages)
- PDF renderer: PDFBox, clipping, text placement, bookmarks, metadata

2. Level 1 — Natural-size PDF (Default export)
- Preserve all columns and rows on the same page when supported (<= 14,400 pt)
- Natural column widths, row heights calculated from wrapped content, preserve blank lines
- No scaling, no horizontal or vertical pagination unless exceeding coordinate limits

3. Level 2 — Extended-size PDF (/UserUnit)
- When natural dimensions exceed 14,400 pt, use UserUnit multiplier U = max(1, max(W,H)/L)
- Coordinate scaling: W_pdf = W/U, H_pdf = H/U, UserUnit = U
- Test with real PDFBox & Android viewers

4. Level 3 — Lossless tiled PDF (Fallback export)
- Row-major tile ordering: row ranges exported across all horizontal column groups left-to-right
- Continuation labels: "Sheet1 | Rows 1-500 | Columns A-AD | Horizontal panel 1 of 7", "Continues right -> AE"
- Bookmarks and metadata

Test on Android Studio emulator / connected ADB device with a big generated excel with many rows and columns.

SECTION 2: COMPREHENSIVE FINDINGS & REQUIREMENTS MAPPING
================================================================================

1. Finding 1 [P2] (Bug): Default page height constant in OfficeConverter.kt
   - Root Cause: Explicitly clarify landscape minimum dimensions. Standard A4 in landscape orientation has width 842 pt (297mm) and height 595 pt (210mm).
   - Fix: Use explicit constants `A4_LANDSCAPE_WIDTH = 842f` and `A4_LANDSCAPE_HEIGHT = 595f` (or `PDRectangle.A4.height` for width and `PDRectangle.A4.width` for height). Set `minOf(maxPdfPageHeight, maxOf(595f, totalRequiredHeight))`.
   - Dynamic expansion: For sheets taller than 595 pt, expand up to `maxPdfPageHeight` (14,400 pt).

2. Finding 2 [P2] (Coverage Regression): Restore separate oversized-row pagination test
   - Problem: The test `testXlsxOversizedRowPaginatesAcrossPagesWithoutTruncation` was changed to expect 1 single page because 60 lines fit under 14,400 pt, eliminating test coverage for the multi-page pagination branch.
   - Fix: Keep two tests:
     (a) `testXlsxOversizedRowDynamicHeightFitsOnSinglePage`: Verifies a 60-line cell dynamically expands page height without artificial A4 cuts.
     (b) `testXlsxOversizedRowPaginatesAcrossPagesWhenExceedingMaxHeight`: Verifies that when content exceeds the max page height (or in a multi-page table), rows are split across pages without losing or duplicating lines, maintaining strict sequential monotonic reading order.

3. Finding 3 [P2] (Coverage Gap): Wide-column test positional assertions across all 25 columns
   - Problem: `testXlsxExtremeColumnsDynamicallyExpandPageWidthWithoutSquishingOrClipping` only asserted column 1 and column 25.
   - Fix: Use `PositionalTextExtractor` to assert:
     - All 25 headers (`WideColumnHeaderPayload_1` through `WideColumnHeaderPayload_25`) are present.
     - Strictly ascending X coordinates: `col[i].minX < col[i+1].minX` for all `i` from 1 to 24.
     - Zero horizontal overlap: `col[i].maxX < col[i+1].minX`.
     - All columns fit within `page.mediaBox.width` with adequate margin.

4. Finding 4 [P3] (Fidelity): Preserve empty lines inside cells
   - Root Cause: `wrapText()` in `OfficeConverter.kt` splits by newlines, then splits each paragraph by whitespace and checks `if (word.isEmpty()) continue`. If an entire paragraph is empty (consecutive newlines `\n\n`), nothing is added to `lines`.
   - Fix: If `paragraph.isEmpty()`, emit an empty string line `lines.add("")` so blank lines between paragraphs are preserved with their vertical height.

5. Audit Report Inconsistency & Documentation Sync
   - Accurately document the 595 pt minimum landscape height and the dual single-page dynamic expansion + multi-page pagination test coverage.

6. XLSX-to-PDF Level 1/2/3 Architecture & On-Device Big Excel Validation
   - Implement Phase 1 (fix findings) & Phase 2/3 (modular layout engine & validation).
   - Generate a large Excel workbook with many rows and columns and execute conversion directly on connected ADB device `3C161H0023500000` / Android Studio emulator.

SECTION 4: BROADER ARCHITECTURAL & EDGE-CASE PLAN
================================================================================

1. Cell Grid Borders with Empty Lines:
   When a cell contains blank lines, the cell's calculated height must account for the empty lines so the cell border encloses all lines with proper padding.

2. Consecutive Newlines at Start or End of Cell:
   `\n\nText\n\n` must preserve both leading and trailing blank lines cleanly without throwing index out of bounds.

3. Massive Column Counts (Level 1 vs Level 3):
   Level 1 handles up to `MAX_PAGE_WIDTH = 14400f`. For 100 columns of width 100 pt = 10,000 pt, Level 1 fits on a single continuous page. Beyond 14,400 pt, Level 3 tiling groups columns into contiguous panels.

4. Strict Monotonic Positional Assertions:
   Checking all 25 columns: for every `i` from 1 to 24:
   `col[i].maxX < col[i+1].minX` mathematically guarantees zero horizontal overlap across the entire table.
